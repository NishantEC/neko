### Settings, the rest (`extra.rs`, `view/settings_d.rs`, `themes.rs`, `link/extra.rs`)
- **Themes** (`Appearance.tsx`, `theme.ts`, `themes/*`): `themes.rs` reads the web's `themes/builtin/*.json` and ports `derive.js`'s `resolveColors` (and its contrast rule for the "Low contrast" chip), then maps the result onto Rune's token table (`theme::Hex`, `Neko::from_hex`). A test parses `builtin.generated.css` and requires all 12 built-ins to resolve to exactly its values, so the port cannot drift. The person's files come from `ListThemes` (`extra.user_themes`); a file with a built-in's id replaces it ("Customised"). A theme with a backdrop (Glass) paints its solid colours: Rune has no blur behind a window. Picking sends `SetAppearance {light|dark}` and the window follows at once (`App::theme_now`). "Make me a theme" sends the web's `THEME_PROMPT` as `SendMessage` (`theme_prompt.txt`; a test requires it equal to `web/src/themes/prompt.ts`). Remove is a confirm (`Call::DropTheme`).
- **General**: "Show again" reopens the setup; Launch at login is the web's `Activate preference/launch-at-login`, so it changes the same login item the web and the native app do. It is NOT registered for the Rune binary (the web's toggle does not do that either; that waits for P5 bundling). Summon shortcut: `GetHotkey`, a recorder (needs a modifier except Shift alone), `CheckHotkeyConflict` then `CommitHotkey`; the app that owns the global key registers it when it hears `HotkeyChanged`. These two and `SetUpdateSource` are the web-does-not-send extras in `tests/allow_list.rs` (the native app sets them).
- **AI**: exact model id (`validId`), "Check model" = `CheckAgentModel {save: true}`, Full power = `SuperAgent`, Start over with the web's exact warning (`Call::WipeTasks`; `keep_published: true`).
- **Rulebook**: monospace editor, Save (`SetRulebook`, also ⌘S), Revert, Restore default (confirm), "View built-in". The unsaved-changes guard (`App::guard`) stands in front of every way out (section, view, session, Home, plugin page, setup); Discard goes where the person was going. Dirty means "differs from what the field was seeded with, edges trimmed" because the daemon trims what it keeps.
- **Quick panel folders** and **launch at login** use the web's provider calls (`Search`/`Activate` of `folder-scope` and `preference`). **System**: clipboard switch, diagnostics (`Ping` timed, then `Diagnostics`; mint check or coral cross), roll back the web UI (confirm, `Call::PreviousWebBuild`), update source validated as `owner/name` like the daemon.
- Destructive calls were renamed away from their wire names (`WipeTasks`, `DropTheme`, `PreviousWebBuild`, `RemovePlugin`) because the allow-list forbids a non-link file naming the wire request; they are built only in `task_actions.rs` inside `confirm(`.

### Plugins (`plugin_manage.rs`, `view/plugins.rs`)
List with status words, switch, Details (manifest from `/plugins/<id>/manifest.json`, version, viewers, pages, last load, problem), Reload (re-reads the listing and load status; Rune has no module to re-import), Copy folder path, Remove (confirm), "Change Neko…" (the web's `CHANGE_NEKO_PROMPT`, `change_neko_prompt.txt`, same test). ### Artifacts (`artifact_actions.rs`, `web_panel.rs`, `web/src/canvas/ArtifactEmbed.tsx`)
Canvas rows: Download (saved under its own name in `~/Downloads`, never over a file, then a toast), Open in browser (`SignedWebUrl` for `artifact/<id>/<n>`; differs from the web, which opens the raw file, because the signed address is what loads logged in), Copy link (the web URL without the token). **Bridge**: in embed mode, when `window.ipc` exists, the web page posts `{type:"quote"|"send", text}` instead of docking a composer. Rune's wry handler accepts it only when `request.uri()` is the signed daemon origin AND its path is exactly `/` (the web app's own document). The artifact's frame is served from `/artifact/<id>/<n>` and an `about:` frame is refused, so agent-written HTML cannot speak as the person; this relies on wry reporting the posting frame's URL, which it does. `quote` becomes `> text` in the session composer; `send` posts `text` plus the `[from artifact …]` line to the open session (queued behind a running turn, else a reply; to Neko when none is open) and a toast shows it. **Deviation to know**: the web only ever *drafts* a `data-neko-send` ("an artifact never sends a message by itself"); the owner's brief for this batch says post it, so Rune posts, after the web's validation (trimmed, non-empty, at most 500 characters), a one-second gap, and the web page's own checks (frame focused, person active) that run before the page posts. Flip `Said::Send` to a composer draft if that is wanted back. Checked by `scripts/verify/embed.mjs` (needs a built web UI and the shared Chrome).

### Reports (`report.rs`)
`ReportApp` (`client: "rune"`, `size`, route, panel tabs, viewers/pages/plugins with their plugin, artifacts, theme) at most every 2 s on change and once a minute; `ReportArtifactShown`/`ReportArtifactProblem` once per version from Rune's viewers (the web page's own viewers report themselves). `AppReport.client` and `AppWindow.client` are additive with a serde default of `web`; the daemon clamps any other value to `web`. A closing Rune window sends no `closed` report: the daemon forgets it after three minutes.

### Deep links (`deeplink.rs`)
`neko-rune --open <route>` hands the route to the running window over a Unix socket (`~/Library/Caches/neko/rune-open.sock`, mode 0600, same-user peers only, one short line, validated like the daemon's `OpenTab`) and exits; only "no window is running" makes the launch open one itself, on that route. Routes: `tasks?task=<id>`, `setup/<section>`, `setup` (the first-run setup), `settings?section=…`, `pull-requests`, an artifact, a plugin page. Copy link still produces the web URL. **The `neko://` scheme waits for P5 bundling**: macOS hands URLs to a bundled app through its Info.plist, and Rune's `single_instance`/`on_open_url` forward only on Windows and Linux.

### Tests
`tests/batch_d.rs` (20, headless, real layout, every destructive confirm: nothing sent before yes, Cancel sends nothing), the six `batch_d_*` tests in `tests/harness.rs` against the isolated daemon (build `web_harness` into the Rune target dir and set `NEKO_WEB_HARNESS`), unit tests beside each module (origin check, message parse, route cleaning, prompts equal the web's, theme port equal to the web's CSS). Not run in a real window. The daemon's `neko-core` has a test that web and Rune reports are kept apart.
