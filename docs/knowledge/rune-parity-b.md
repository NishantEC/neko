## Rune parity batch B: the work views (2026-11-17)

Code: `apps/neko-rune/`. Behaviour is the web file named per item, visuals are `docs/design/rune/polish-spec.md`. Pictures: `docs/design/rune/batch-b-*` (synthetic, `scripts/snap-batch-b.sh`, scenes `bb-*` in `src/scenes_batch_b.rs`); the pairs on the owner's copied data are `bb-*-{web,rune}.png` in `/tmp/neko-polish` (never committed, `scripts/polish-pairs-b.sh`).

### All sessions: List, Board, Tree (`board.rs`, `view/board.rs`, `view/tree.rs`, `view/all.rs`)
- A segmented control in the header band chooses the layout; it persists in Rune's prefs (`all-layout`, two more `Prefs::open` sites, the allow-list test counts six). A stage select joins the search, workspace select and overflow, and applies to all three layouts (the board then shows that column alone, like the web's stage tab).
- **Board** (`work/board/*`): five 280 point columns (12 gap) in the web's order, sideways scroll. Cards: foreground 3% (4% light), radius 10, padding 12, title 13.5 on two lines, meta glyph, state words, workspace, age; unseen dot top right; the one action (Approve, Answer, Start again) lies over the end of the state line on hover or focus and is first in the right-click menu (then Open and the shared task menu); selected or J/K card has a 2 point Iris ring.
- **Drag** is Rune's `on_drag`: the column under the pointer is `floor((grab_x + travel) / 292)` from the source column (no layout query), the carried copy is a pinned element in the overlay layer. `board::decide` is `work/board/moves.ts` + `moveCommand`: Start work (`StartTask`), Mark done (`CompleteTask`), Cancel the task (the daemon's cancel, behind the same dialog as the web); anything else is refused with the web's words (a toast), sends nothing, the column does not light up and the cursor is not-allowed. Travel under 6 points is a click; the press that ends a carry is swallowed (`suppress_press`). Esc cancels.
- **Tree**: parent and child tasks only (`splits` subtasks and `follow_up_of`, `Summary::parents`), 20 points per level, chevron folds (a folded row's descendants stay hidden, a loop of parents shows once). Left out of the web's Agent tree on purpose: the Neko root, watch nodes and per-run nodes (the brief asks for parent and child tasks).

### Pull requests (`link/prs.rs`, `pull_requests.rs`, `view/prs.rs`)
- `PrRow` is the web's `pullRequestRow`; groups are the web's `VERDICTS` order and titles (not the brief's example names). Sidebar row after Calendar, count = open ones that wait on you (Ready, Close, Needs your call, failing checks, review required), none at 0.
- Row: glyph, `#n · repo` faint, title, author, checks, age; on hover the actions replace checks and age: the "Merge when ready" switch (`SetMergeWhenReady`), Close, Open task, Open on GitHub, all in the right-click menu. Close is a dialog with a reason (prefilled with the agent's suggestion, the button is off while it is empty) and a coral button; `Ask` gained `field`, `list` and `more` for this and for "Merge all ready" (a dialog that lists them, then one `SetMergeWhenReady` each, as the web's `mergeAll`). The overflow holds "Review pull requests" (confirmed), merged and closed, and "Merge without review" per repository (a confirm when turning it on). "Check GitHub" is a quiet button.
- The destructive Call is named `Call::ClosePr`: the allow-list forbids a non-link file from naming the wire request, and `ClosePullRequest` is the wire name.
- Different from the brief's wording: the snapshot has no check counts and no GitHub author, so the checks read "passing", "N failing" (coral), "running", "no checks" and the author is the agent runtime that ran the task.

### Details tab (`view/context_info.rs`, `panel::Section`)
- "Info" is "Details" (`Tab::Details`, same icon). Sections, each folding (`Panel::toggled`): Risk assessment (when the task has one), Parallel work (subtask rows that open that task, "Propose parallel work" = `ProposeSplit`), Decisions (`Detail::decisions`, the web's `latestDecisions`), Working copy (`~/` path middle-truncated, Reveal in Finder, Copy path), Info (the old tab, same keys), Activity log (folded by default, newest first, 32 point rows, 150 shown then "Show N earlier").

### The session composer's `/`
The web's task reply box has no `/` menu (only Home's composer does), so the session gets the web's command list (`ChatInputSlash.ts`) minus the ones that are Neko's own conversation (`/plan`, `/remember`, `/forget`, `/recall`). `/models` opens the session's own chip, `/help` writes `/` here. Keys as the ask box: Up, Down, Return or Tab accept, Esc closes.
