## Rune parity batch A: the web's behaviour in the Rune client (2026-11-16)

Code: `apps/neko-rune/`. Brief: behaviour is the named web file, visuals are `docs/design/rune/polish-spec.md`. Pictures: `docs/design/rune/batch-a-*.png` (synthetic, `scripts/snap-batch-a.sh`); real-data pairs stay in `/tmp/neko-polish` (`scripts/polish-pairs.sh`, `NEKO_RUNE_PREVIEW=`).

### The allow-list is a mirror (`tests/allow_list.rs`)
Rune may send `WEB_SENDS` plus `RUNE_EXTRAS`. `WEB_SENDS` is read from `web/src` (the first argument of `command(`, `run(`, `send(`, `request(`, what `Workbench` wraps, the board's move table); a sub-command of `Crew`/`Goals`/`Checkpoints` counts when the web's sources name it. `RUNE_EXTRAS` is each request with its reason (CreateTask/StartTask, the panel's SignedWebUrl/TaskFolder/ArtifactFile/ArtifactsForTask/PluginViewers/PluginPages, the reads Rune made first, ReplyToTask which the web sends through its chat stream, the two Settings limits). `NEVER` is only `McpBridge` and `SaveArtifact` (agents' lease calls). A destructive request (delete, start over, retry, stop all, clear finished, close a PR, remove a theme, roll back) is only built inside `confirm(` in `task_actions.rs`; a test scans for it. The HTTP client `link/http.rs` reaches only `/api/attachments`, `/api/files`, `/api/plugins/*`, with the token `SignedWebUrl` returns, as a Bearer header (the daemon accepts the query token on `GET /` only).

### What was built, by the web file it follows
- **Header and badges** (`view/session.rs`): opaque region fill, an 8 point fade under the header and goal rows; "Ready to review" in sky; Queued, Completed, Cancelled have none. **Model chip** (`runtime_pick.rs`, `view/runtime.rs`, `ChatInputRuntime.tsx`): catalog from `AgentModels`, pins per axis, a model change drops only the pins it cannot honour, "Check & apply" sends `SetConversationRuntime` on `task:<id>` (Neko's ask chip: `home:<profile>:<workspace>`). The daemon's refusal is shown verbatim.
- **Task actions** (`task_actions.rs`, `taskActions.ts`): one list for the "..." menu, the row right-click and the palette. Rename edits the header title (Enter saves, Esc cancels). Delete, Retry, Stop, Cancel, Stop all, Clear finished go through a modal dialog (`view/dialogs.rs`), coral for the destructive ones. ⌘⇧Esc and the account menu: "Stop all N running agents?". **All sessions** (`all_sessions.rs`): the web's stages, search (`/`), workspace filter, J/K, overflow.
- **Composers** (`compose.rs`, `view/compose.rs`): `/` and `@` popover above Neko's ask box (32 point rows, 8 visible, the web's command list, `/api/files` 180 ms after the last key); "+" picks any file; drops anywhere on the session region show the dashed overlay; chips upload over HTTP and their references join the message; the queue tray (Edit in place, Send now, Cancel, ⌥↑, ⌘↵ = `InterruptAndSendMessage`, `DiscardQueuedMessage`); the message right-click menu; finished replies draw `csv`/`tsv` fences as tables and `3d` fences naming an artifact as a card that opens the Canvas.
- **Palette, shortcuts** (`palette.rs`, `shortcuts.rs`): 640 wide, top at 20%, 44 field, 36 rows; Sessions, Go to, Actions, Appearance, Plugins. `?` overlay in two columns; ⌘B; ⌘↵ approves and Esc declines a waiting decision outside a field. Right-click on selected text: Ask Neko about this, Search for. The workspace switcher (`scope.rs`) scopes the list, Routines, the Calendar's Neko rows and Home's composer, and persists in Rune's prefs next to the layout.
- **Inbox** (`view/neko.rs`): hover Use the default then Mark done (`ClearNeedsYou`), right-click the same plus Open; "Closed recently" (3 days, folded, reason and Reopen = `ReopenNeedsYou`). **Routines**: Every/Daily cadence editor (`pages.rs`); **Calendar**: Month grid (6x7, 28 point headers, three chips, +N) and the event popover with Join meeting (the web's host list).
- **Feedback** (`toasts.rs`, `attention.rs`, `dock.rs`): up to three toasts, bottom centre, 40 high, radius 12, 4 s, an optional button. The web shows no Undo on any toast, so none is built. Pushed events: AttentionChanged re-reads the counts, OpenTab routes, ThemeChanged re-reads the appearance, QuotaChanged refreshes Usage, WebUpdated is ignored. The Dock badge shows the web's title count (`needsUser`: waiting + failed + review + pending decisions) through objc2 (`NSApp.dockTile`, main thread only).

### Differences left on purpose
No Tabs shortcut group (no tabs); the palette lists the two themes Rune paints and plugin pages, not plugin commands (they live in the web runtime); plugin-registered fences other than csv/3d stay code with a note; the `/` popover is on Neko's ask box (the web's Home composer), not the session reply box; All sessions hides failed and cancelled until asked (the brief), the web's list shows them.

### Tests
`tests/batch_a.rs` (33, headless, real layout), the five `batch_a_*` tests in `tests/harness.rs` against the isolated `web_harness` (rebuild it first: an old binary lacks `SignedWebUrl`), unit tests beside each module. A scan test caught a real trap: `link::pushed` events changed the link test's event order.
