**4. Proposed native reuse constraints**

1. **Keep the native shell contract.** Preserve `NavigationSplitView`, `stableSplitPane`, top safe area and toolbar hit regions; restyle/reorder within them. Maintain system/light/dark, 880pt management / 760pt chat, 32pt insets and native accessibility/focus. `stableSplitPane` prevents an AppKit layout-loop crash. [Constraint](/Users/nish/Documents/neko/native/NekoKit/Sources/NekoNative/DesignSystem.swift:120), [layout/material guidance](/Users/nish/Documents/neko/docs/architecture.md:59).
2. **Keep navigation and drafts above screen composition.** Retain workspace/profile/ticket scope, return page and filters in `AppModel`; reuse the AppKit editor and acknowledged-revision clearing. Home send/queue/stop and ticket redirect remain separate adapters; payload limits are 4 KiB/2 KiB, and drafts survive navigation, not app restart. [State](/Users/nish/Documents/neko/native/NekoKit/Sources/NekoNative/AppModel.swift:4), [composer contract](/Users/nish/Documents/neko/docs/architecture.md:90).
3. **Let daemon facts drive badges and actions.** Use task statuses/approved child IDs, receipt-backed checks and current-versus-historical results. Do not label reviewer phases as extra teammates or acceptance as merge. Preserve command guards, errors and loading/empty states; the two-second heartbeat is connection health, not progress. [Status/team](/Users/nish/Documents/neko/native/NekoKit/Sources/NekoNative/TaskTeamSummary.swift:7), [result presentation](/Users/nish/Documents/neko/native/NekoKit/Sources/NekoNative/TicketsView.swift:68), [heartbeat](/Users/nish/Documents/neko/docs/architecture.md:41).
4. **Keep runtime and authority independent.** Use discovered model/effort/speed capabilities, per-conversation pins and Settings defaults. Do not hardcode Design lab catalog availability, imply quota-aware failover or infer granted tools from plugins/memories. Sources remain user-owned MCP connections with explicit scope/trust; built-in Linear commands are retired. [Runtime contract](/Users/nish/Documents/neko/docs/architecture.md:181), [retired connector](/Users/nish/Documents/neko/crates/neko-daemon/src/workbench.rs:141).
5. **Use glass for controls and keep evidence legible.** Reuse macOS 26 system glass with the material fallback and opaque content surfaces. The decorative pearl is pointer-driven, with no idle timer and motion/transparency/contrast fallbacks; it is separate from system glass. Any sample UI promoted into production needs a real adapter and populated/empty/error acceptance. [Glass helper](/Users/nish/Documents/neko/native/NekoKit/Sources/NekoNative/DesignSystem.swift:423), [pearl](/Users/nish/Documents/neko/native/NekoKit/Sources/NekoNative/DesignLabOrb.swift:3), [current design contract](/Users/nish/Documents/neko/docs/architecture.md:64).
