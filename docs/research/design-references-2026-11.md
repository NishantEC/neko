## 2. Design theory (principles, each with evidence)

Quotes are one short phrase at most; the rest is paraphrase.

### 2.1 Capy

| # | Principle | Evidence |
|---|---|---|
| C1 | **Tell the person only what needs them.** A Captain's job is to surface decisions and blockers, not every crew update; its digest has three parts (needs you, new, in progress) and is rewritten when crew state changes. | `capy:https://capy.ai` (home page phrase "only tell you what needs you"); `capy:https://docs.capy.ai/captains.md` |
| C2 | **"Needs you" is a flag, not a status.** Status is what the agent is doing (Working, Waiting, Failed, Idle); Needs you is an overlay for questions, decisions, env vars, approvals, hand-offs and credit requests. The two never compete for one slot. | `capy:https://docs.capy.ai/threads.md` |
| C3 | **Hold the reader's place.** Finished threads open at rest; rows being read stay put when a long thread re-lays out; steps in a working thread no longer blink; requests stay open until answered and the thread keeps a line that reopens them. | `capy:https://capy.ai/changelog` entries 0.9.2 ("Threads hold your place"), 0.7.0 ("Less flashing") |
| C4 | **Pause, do not fail, on money.** When credits run out, threads pause and the row says whether the model or the machine needs funding, with options such as a free model. | `capy:https://capy.ai/changelog` 0.9.2 |
| C5 | **Say what you are waiting on, in the last line.** A Waiting thread names the event ("waiting on a pull request's checks") and the event is a link; running watches are listed above the composer, each with Stop watching. | `capy:https://docs.capy.ai/async-work.md` |
| C6 | **Confidence is a label, not a tone.** A review finding states a failure scenario, severity (High, Medium, Low) and confidence (Confirmed or Investigate); status is Open, Resolved or Irrelevant, and a person can override the agent's triage. | `capy:https://docs.capy.ai/review.md` |
| C7 | **Where the work runs is always visible.** Every thread row shows whether it runs in the cloud or on a device; the composer's machine menu can move it. | `capy:https://capy.ai/changelog` 0.6.0, 0.9.0; `capy:https://docs.capy.ai/desktop.md` |

Capy states no written visual principles. The only design-theory statements are the product commitments above.

### 2.2 T3 Code

| # | Principle | Evidence |
|---|---|---|
| T1 | **Performance is a design rule.** Dropped frames, "a lying spinner" and a stale label are defects; no continuously repainting animations because they peg the GPU on high-refresh displays. Audits cover payload size, GPU-heavy CSS animation and list rendering. | `t3:AGENTS.md:210` and the "Performance without compromise" section; `t3:docs/internals/performance-regressions.md` |
| T2 | **Controls own their look.** A primitive's appearance is picked by `variant` or `size`, never restyled with `className`; a lint rule fails the build. Layout classes belong on the parent. A look used by one feature stays in that feature. | `t3:AGENTS.md:200`; `t3:docs/internals/web-ui.md` |
| T3 | **Compose from slots.** The composer banners are the reference: one object of small slots, plus a stack component that owns only priority, expand/collapse and dismiss. New notices reuse the slots. | `t3:docs/internals/web-ui.md` ("Composition"); `t3:apps/web/src/components/chat/ComposerBanner.tsx` |
| T4 | **Reverse states exist.** If you add a way in, add the way out and the way to see it: snooze needs unsnooze, close needs reopen. "A one-way door is a bug." | `t3:AGENTS.md` ("Hit every surface") |
| T5 | **UI stays dumb, complexity at the adapter boundary.** Server owns state, settlement and notifications; clients render. | `t3:AGENTS.md:197` |
| T6 | **Visual bugs are proved by pictures, not tests.** Before and after captures for a visual change; a short video for motion or timing. | `t3:AGENTS.md` (testing section, lines about visual proof) |
| T7 | **Minimal, obvious, few concepts.** "Simple systems, and software that feels obvious"; do not keep complexity because it exists. | `t3:AGENTS.md` ("A note from" the maintainer) |
| T8 | **Quiet by default for finished work.** Settled threads leave the active list; tool calls can be hidden (Hide successful, Hide all, Zen) with approvals, questions and errors always shown. | `t3:docs/user/thread-sidebar.md`; `t3:docs/user/activity-log.md` |

### 2.3 DeepSeek (harness and superagent)

| # | Principle | Evidence |
|---|---|---|
| D1 | **Alignment and grouping before tokens.** A review judges, in order: the task and groups, shared axes across the whole region, group-internal relationships, then hierarchy, state, geometry, colour. Legal tokens do not excuse bad alignment; one clean crop does not prove a page. | `dsh:docs/ui-design-review-cases.md` ("What a review must judge", "Review the entire page or modal as one unit") |
| D2 | **Gaps carry meaning: external larger than internal.** Title-to-actions gap must exceed the gaps inside the action cluster; a heading sits closer to its own content than to the previous section; do not subtract the same amount from every gap when densifying. | `dsh:docs/ui-design-review-cases.md` (examples G1 to G4) |
| D3 | **Radius is chosen by role first, then size.** Width, wrapping and content growth never promote a radius. Six tiers: R4 detail, R8 compact control, R12 standard control, R16 grouped content, R20 independent card, R28 main surface. Nested: inset arrangement subtracts, flush fill is clipped by the enclosure, independent child card takes its own tier. | `dsh:docs/ui-radius.md` ("Select the radius", "Nested geometry and hover") |
| D4 | **Edges come from one source.** Elevated surfaces take `border: 0` and a shadow whose first layer is a 0.5 px ring; a neutral border paired with an elevation shadow is rejected by a stylesheet test. Flat neutral borders are 0.5 px hairlines. | `dsh:docs/web-styling.md` (component rules); `dsh:packages/client/ui-theme/src/styles/gradient-shadow-text.css:31-40` |
| D5 | **State meanings are stable.** Selected, hover, focus and disabled each have one meaning; the selected row beside a hovered row, and selected plus focus, must stay distinguishable. | `dsh:docs/ui-design-review-cases.md` (section 5, example S1) |
| D6 | **Reuse before adding; one owner per rule.** Components come from a primitives catalogue; exceptions are pinned by file, selector and declaration in an expected-values file, not by exempting packages. | `dsh:.agents/skills/dsh-client-ui-ux/SKILL.md`; `dsh:docs/ui-radius.md` ("radius exception record") |
| D7 | **Take as little human attention as possible and give as much value as possible.** Every message, setting, panel element and paragraph costs attention and is removed unless it gives more. | `dss:docs/000-philosophy.md` |
| D8 | **A panel answers three questions in order:** does anything need me now, is the system healthy and doing the right things, what is the history of one piece of work. Every element answers one of them or is removed. | `dss:docs/005-panel.md` ("Three questions", "Principles") |
| D9 | **Honest state.** A count equals the length of the list it links to; no state contradicts another fact; a label says whom a row waits for and what it needs, not an internal code; healthy states take no space; one save bar, visible only while changes exist. | `dss:docs/005-panel.md` ("Principles" 2, 5, 6, 7) |
| D10 | **Feedback by lifetime.** Transient result: app-wide toast hosted where it survives its source panel; a pending state is never a toast; a failed operation keeps the data visible; surface-owned failure is an in-place notice with Retry. Lists load as skeletons, other pages as one bare spinner. | `dsh:.agents/skills/dsh-client-ui-ux/SKILL.md` ("Interaction and feedback") |

## 5. Patterns to adopt (ranked)

Ranking is by value to an agent that runs for hours, divided by effort. Licence column: **MIT** means readable code may be copied with the notice kept (Neko already keeps one for T3 files); **ideas only** means re-describe, never copy. Each pattern was checked against the design doc's section 0 and section 9 and against `N:DESIGN.md`; where Neko already has part of it, the "change" says what the delta is.

### 1. A "Waiting" state that is not "Working", plus receding rows (and a number that is a word)

| | |
|---|---|
| Pattern | Four row states, not three: **Working** (live, shown with a ticking duration), **Waiting** (the agent ended its turn and is parked on a timer, CI, a subagent or a long command: still, muted, with its age), **Needs you** (an overlay, never a status), **Done unseen**. Rows that need nothing recede to about 75% text and come back on hover or when selected. While something is pending, the trailing age is replaced by one word ("Approval", "Answer"). |
| Evidence | T3 status words and the `shouldRecede` rule: `t3:apps/web/src/components/Sidebar.logic.ts:894-916,928-958`; `t3:apps/web/src/components/sidebar/SidebarThreadRow.tsx:783-843,1636-1660`. T3 folds "waiting" threads into a collapsed Working section: `t3:docs/user/thread-sidebar.md`. Capy: Waiting is a separate state and Needs you a separate flag (`capy:https://docs.capy.ai/threads.md`); the last line names the event (`capy:https://docs.capy.ai/async-work.md`). DeepSeek: precedence and the trailing word (`dsh:packages/client/ui-workspace/README.md:78`). |
| Why it works for hours-long runs | A parked agent waiting on CI for two hours must not look like one burning tokens. Without a Waiting state the list is a wall of "in progress" and the person stops trusting it. Receding rows make the few rows that need the person the only high-contrast things on screen. |
| Licence | T3 and DeepSeek MIT (logic is small enough to re-write); Capy ideas only. |
