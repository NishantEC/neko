# Fixing the holes before more features (2026-11-20)

The system map (`docs/architecture/system-map-2026-11.md`, §9 "Seams and inconsistencies") found places where one idea is built several ways, and one safety gap. The owner's order: fix the holes in batches, then sweep again, then redesign the UI and UX. Each batch is gated (`scripts/check.sh` fully green, privacy check clean) and pushed on its own. Decisions below are the orchestrator's; builders implement them exactly.

## H1 · One admission gate for every agent start (safety, first)

**Problem.** Watch wakes start agent runs without asking the machine steward or the daily spend ceiling. Other run kinds each check their own subset.

**Decision.** One function, `admission::may_start(kind, workspace) -> Admit | Hold(reason)`, is the only way any agent run starts: tickets, goal turns, routine runs, watch wakes, cat turns, the skill curator, the judge and the triage model calls. It checks, in order: machine steward `holding`; the steward `cap` (counted from H3's single count); the daily spend ceiling; quiet hours where the kind is proactive. A held start is not an error; it is retried by its own tick and shows "Held: <reason>" where the person can see it. Tests: one per kind proving it is refused while holding and while over the ceiling.

## H2 · One "needs you" building block

**Problem.** "Needs the person" is stored seven ways; goal and improvement questions hide inside never-run routines (`crates/neko-daemon/src/routines.rs` around line 540).

**Decision.** One store and type, `NeedsYouItem { id, source: Goal | Routine | Improvement | TicketQuestion | Approval | Cat | Pack, source_id, question, default: Option<String>, deadline_ms: Option<i64>, state: Open | Later(until_ms) | Dismissed | Settled, created_ms, settled_ms }`, rows of its own. Every producer writes here; the Inbox, the phone push, the morning briefing, the Rune and web lists and the cats read only from here. Actions are one request: `NeedsYou(Answer{id,text} | UseDefault{id} | Later{id,until} | Dismiss{id})`. The fake-routine trick is removed with a one-time migration of open items. This becomes the base for Phase 1's needs-you work (B3 builds on it, not beside it).

## H3 · One run launcher and one count

**Problem.** Run launching and "agents running" differ per call site; the steward cap counts only ticket workers.

**Decision.** One launcher, `runs::start(spec, kind)` (after H1's gate), records every live run in one in-memory registry `RunningRuns` (kind, task or cat id, pid, started). The steward cap, the sidebar strip, the activity pill and Usage read that registry. Routine, watch, cat, curator and judge runs are counted.

## H4 · Cost has one source

**Problem.** Cost is read from three places; the daily ceiling reads task events and routine runs, never the ledger as a whole.

**Decision.** The usage ledger (`usage_events`) is the only source of cost. The daily ceiling, per-session and per-cat cost, the Usage page and receipts read the ledger. Every paid call (including judge, triage and curator calls) writes a ledger line (`kind` says which). Other cost readers are removed.

## H5 · One change signal, one storage convention, one small-model helper

**Decision.** Every stored change bumps the one data revision clients already wait on; remove the two other signals. Storage convention: rows per entity through `Db` methods; anything that still stores entities in the snapshot blob is listed in the doc and moved when next touched (not in this batch). The cheap model call copied six times becomes one helper, `small_model::ask(prompt, purpose)`, which also writes its ledger line (H4).

## H6 · Docs match the code

**Decision.** Fix `docs/architecture.md` (Rune does write; `tests/read_only.rs` does not exist), link the system map from it and from `CLAUDE.md`, and record H1–H5 in the knowledge docs they touch.

## Order

H1 → H2 → H3 + H4 (one batch) → H5 + H6 (one batch) → **Sweep 2**: rerun the seam analysis of the system map on the new code and list anything left, before any new feature slice.
